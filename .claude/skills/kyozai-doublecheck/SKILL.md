# 教材ダブルチェック

## なぜこれがあるか

教材の検査は、これまで**投入時（サーバー側）にしか無かった**。生成した手元では何も回らないので、
「作る → 貼る → 怒られる → 直す」が最低1往復、確定で入っていた。しかもリークや偏りの検査は
バッチ全体の統計でしか出ないため、往復の単位が単元まるごとになる。

さらに悪いのは、投入時ですら見つからなかった欠陥がある。

- 正解と同じ語義のダミーが並ぶ（シス単は223語＝11%が他の語と語義を共有）→ **生徒が解いて発覚**
- ダミーの母数が足りず同じ語が最大6回並ぶ → **生徒が解いて発覚**
- 誤答が特定の勘違いに対応しておらず、誰も選ばない＝実質3択 → **設計しなおし**
- cloze の規則（活用形リーク・空所直前の a/an・ダミーの品詞混在）→ **仕様書に書いただけで検査は無い**

このスキルは検査を左に寄せる。**生成したら、ユーザーに見せる前に自分で通す。**

## 手順

### 0. 置き場所の確認（先に）

`line-harness-oss` は public リポジトリ。**問題文・単語・例文をここにコミットしない。**
生成物はリポジトリ外（`.company/英弱ニキ/lms/` 配下や作業用ディレクトリ）に置き、
検査はそこを指して走らせる。規則の正本も `.company/英弱ニキ/lms/grammar/02-generation.md`、
`.company/英弱ニキ/lms/vocab/12-cloze.md`。読める環境なら必ずそちらを先に読むこと。
このスキルが持っているのは、正本から機械検査に落とせる部分だけ。

### 1. L1 — 機械検査

```bash
node .claude/skills/kyozai-doublecheck/scripts/check.mjs --type grammar <path>/questions.tsv
node .claude/skills/kyozai-doublecheck/scripts/check.mjs --type vocab   <path>/words.tsv
```

`--json` で機械可読の出力。エラーがあれば終了コード1。

TSV と JSON の両方を受ける。**誤答の勘違いラベル（`distractor_notes`）と単元（`sub_category`）は
TSV では運べない**ので、それらを付けたなら JSON で検査すること。TSV の正解番号は1始まり、
JSON の `answer` は0始まり。ここの取り違えが最頻の事故なので、変換したら必ず検査を通し直す。

**10問／10語未満で回しても意味が薄い。** 位置の偏り・長さのリークはバッチ統計でしか出ない。
1単元ぶんまとめて食わせること。少量ずつ検査して「警告なし」を集めても、何も保証していない。

検査は `apps/worker/src/routes/grammar.ts` の `inspect()` と同じ規則を手元で回すもの。
TSV の読み方（正解番号を末尾から探す等）もサーバーに合わせてあるので、
ここを通れば投入時の列ずれで落ちることはない。**サーバー側の規則を変えたら、こちらも合わせる。**

### 2. L2 — セルフ受験（solve-back）

機械で見えるのはリークの形だけ。「その誤答を選ぶ人が本当にいるか」「正解が唯一か」は、
**解かせてみないと分からない。** 手順は `references/solve-back.md` にある。読んでから回すこと。

3通りを回す。全問やると高いので、L1 が疑った問題（出力の「L2で優先して見る」）＋
ランダム抽出で、1単元あたり10〜15問を目安に。

1. **選択肢を隠して解かせる** → 解けたら問題文が答えを漏らしている
2. **問題文を隠して選択肢だけ見せる** → 解けたらリーク（長さ・形・不自然さ）
3. **勘違いを持つ生徒として解かせる** → 狙った誤答を選ばなければ、そのダミーは死んでいる

3 が本命。`distractor_notes` を書かせる縛りは「書けたか」しか見ていない。
「書いたとおりに機能するか」を見られるのはここだけ。

### 3. 報告

**指摘と修正案を出す。適用は確認を取ってから。** 誤答の作り直しには教育的判断が入るので、
黙って直すと何を直されたか気づけない。

この形で出す。

```
## ダブルチェック結果（<単元名> / N問）

### 直さないと投入できない — X件
- No.12 選択肢が重複（「to do」「To do」）
  → 誤答2を「doing」に。現在分詞と混同する層を拾える

### 見て判断してほしい — Y件
- 正解が3番の問題が48%。位置をばらけさせる
  → No.4, 9, 15… の正解を2番/4番へ移す（誤答の順序も入れ替え）

### セルフ受験で落ちた — Z件
- No.27 選択肢を隠しても解けた。問題文の "since" が答えを決めている
  → 時制のヒントを問題文から外し、選択肢側で問う形に
- No.8 誤答3「仮定法だと気づかず時制を動かしていない」を、その勘違いを持つ生徒役が
  選ばなかった（正解を選んだ）。この誤答は誰も取らない
  → 「had known → knew」の形に変え、直説法の過去と見分けさせる

### 問題なし — W問
```

数字は必ず出す。「いくつか偏りがあります」では直す判断ができない。

## 規則の一覧

何をどう見るか、なぜそれが問題なのかは `references/rules.md`。
新しい欠陥を見つけたら、**そこに追記して `check.mjs` に落とす。**
仕様書とコミットメッセージにしか書かれていない規則は、次の生成で必ず破られる。

## 投入まわりの注意

- 文法問題の投入は管理画面（`/grammar` の問題集）か API。**1行でも壊れていたら何も入らない。**
- 単語の投入エンドポイントは `example` / `example_ja` / `pos` を受け取らない。
  cloze データは `d1 execute` で直接入れることになるので、**サーバー側の検査を一切通らない。**
  L1 を飛ばすと本当に誰も見ていない状態で本番に入る。
- スキーマに足りない列があるなら、**生成を始める前に足す。**
  1000問作ってから列を足すと全部作り直しになる（`062_grammar_distractors.sql` がその教訓）。
