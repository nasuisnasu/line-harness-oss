## エラー（成立しない）

投入は1行でも壊れていたら**何も入れずに落ちる**。半分だけ入った状態がいちばん厄介で、
どこまで入ったか分からないまま再投入すると番号がずれるため。

| 規則 | なぜ | 出典 |
|---|---|---|
| 選択肢を重複させない（空白・大小文字を無視して比較） | 「to do」と「To do」が並ぶと答えようがない | `inspect()` |
| 正解の添字が選択肢の範囲内 | TSV は1始まり、JSON は0始まり。取り違えが最頻の事故 | `parseQuestionTsv` |
| 空の選択肢を作らない | 実質3択になる | `inspect()` |
| 問題番号・語番号を重複させない | `UNIQUE(book_id, no)` に当たって投入が落ちる | 060 |
| 同じ問題文を2度出さない | まとめて生成させると同じ形が混ざる | 検査で追加 |
| 例文に対象語をそのまま書かない | 答えが読めてしまう | 検査で追加 |

## 警告 — 選択肢が答えを漏らす

**バッチ全体の統計でしか出ない。** 少量ずつ検査しても検出できないので、1単元ぶんまとめる。
閾値はいずれも40%（`inspect()` と同じ）。

| 規則 | なぜ | 出典 |
|---|---|---|
| 正解がいちばん長い選択肢になる問題を40%未満に | 正解だけ丁寧に書くと、長さで当たる | `inspect()` |
| 正解の位置を散らす（同じ番号が40%未満） | 番号で当たる | `inspect()` |
| 正解だけ語数が浮く問題を40%未満に | **1問ずつは警告しない。** 文法問題は正解の形が構造的に長くなる（`would have done` は3語だが誤答の `did` / `had done` は1〜2語）。直しようのない指摘を出し続けると警告そのものが読まれなくなる。問題は「いつも正解が浮いている」という systematic なパターンのほう | `inspect()` |
| 正解の文言を問題文に出さない | 空所がすでに埋まっている | 検査で追加 |
| 問題文に空所 `( )` か下線 `[ ]` を置く | 何を答えるのか分からない | 060 |

## 警告 — 誤答が仕事をしていない

**4択問題は生徒の頭の中についての4つの仮説。** 正解＝理解している、誤答3つ＝それぞれ特定の勘違い。
どの勘違いにも対応しない誤答は枠の無駄で、誰も選ばないのでその問題は実質3択になる。

| 規則 | なぜ | 出典 |
|---|---|---|
| 誤答すべてに `distractor_notes`（勘違いのラベル）を付ける | 生成時に「なぜそれを選ぶ人がいるのか」を書かせる縛りになる。書けない誤答は作り直し。管理画面で「5人中4人がこの誤答＝現在完了と since の混同」まで一目で見えるようにもなる | 062 |
| 解説を必ず書く | 文法テストは解説が本体。無いと復習にならない | `inspect()` |
| 単元（`sub_category`）を付ける | 分野（21）は粗すぎて「関係詞が弱い」までしか言えない。単元（140）が出題と苦手判定の軸 | 061 |

ラベルが付いているかは機械で見えるが、**そのラベルどおりに機能するかは見えない。**
`solve-back.md` の3番目（勘違いを持つ生徒として解かせる）で確かめること。

## 例文穴埋め（cloze）の規則

| 規則 | なぜ | 出典 |
|---|---|---|
| 空所には必ず原形（名詞は単数）が入る文脈にする | 活用形が答えを教える | 2e3eb5e / 063 |
| 空所の直前に a / an を置かない | 母音か子音かで答えが絞れる | 2e3eb5e |
| ダミーは同じ品詞から選ぶ | 品詞が混ざると消去法で当たる | 2e3eb5e |
| 空所以外は共通テストレベルまでの語彙にする | 空所以外で詰まると、測っているものが変わる | 2e3eb5e |
| 例文の訳を付ける | 結果画面で「どの文でどう使えなかったか」を見せる。単語と訳だけでは復習にならない | a98d42e |

品詞は必ず偏る。ターゲット1900の実測で動詞760・名詞722・形容詞405に対し、副詞9・前置詞3・接続詞1。
**同品詞のダミーが3つ揃わない語が出る**（実測13語＝0.7%）。揃わないときは条件を外して埋めるので、
その語は品詞混在の選択肢になる。検査はその件数を出すところまでやる。

語彙レベルの検査だけは機械化していない。語彙リストが `.company` 側にあるので、
読める環境ならそれと突き合わせる。読めなければ L2 で見る。

## 4択のダミー生成（単語テスト側）

問題データそのものではなく**出題時の実装**の話だが、生成した単語帳の性質が直撃するのでここに置く。

| 事象 | 中身 | 出典 |
|---|---|---|
| 正解と同じ文言のダミー | シス単は223語（11%）が他の語と語義を共有（「すばらしい」だけで7語）。選択肢に同じ文言が並ぶと答えようがない。発生率は20問あたり0.4%程度だが、起きると理不尽 | 6cafe2c |
| ダミーの枯渇 | 出題語をダミーに優先して使っていたため、20問・延べ60枠に対しダミーが22種類しか出ず、同じ語が最大6回並んだ。サーバーが返すダミーを8語→90語（cloze は150語）に増やして解消 | 248eab1 |

**単語帳を新規に作ったら、語義の重複率を必ず出す。** 重複が多い単語帳は、
出題側のダミー除外が効いているかを確認してから投入する。

## 投入運用の事故

| 事象 | 対処 | 出典 |
|---|---|---|
| 半分だけ投入される | 1行でも壊れていたら何も入れない | `inspect()` 前文 |
| 正解番号の0始まり／1始まり | TSV は1始まり（画面で見える番号と揃える）、JSON は0始まり | `parseQuestionTsv` |
| 少量ずつ投入すると統計警告が出ない | 1単元ぶんまとめて投入・検査する | `inspect()` 前文 |
| 列を後から足して全部作り直し | **生成を始める前にスキーマを足す** | 062 |
| 単語の投入 API が `example` / `example_ja` / `pos` を受け取らない | cloze は `d1 execute` で直接入れる。サーバー側の検査を一切通らないので、L1 を飛ばすと誰も見ていない状態で本番に入る | `routes/vocab.ts` |
| 問題データを public リポジトリにコミット | `line-harness-oss` は public。そのまま公開転載になる | 060 |

## 機械で見えないもの

ここから先は `solve-back.md` の担当。

- 正解が本当に唯一か（他の選択肢でも成立しないか）
- 誤答が本当に選ばれるか（ラベルどおりの勘違いを持つ生徒が取るか）
- 解説が問題と噛み合っているか（別の問題の解説が紛れていないか）
- 日本語訳が自然で、かつ答えを漏らしていないか
- 例文の語彙が想定レベルに収まっているか
- 単元のラベルが中身と合っているか
