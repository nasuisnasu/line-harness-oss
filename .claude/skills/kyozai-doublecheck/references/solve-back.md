# セルフ受験（solve-back）

機械検査で見えるのはリークの**形**だけ。「その誤答を選ぶ人が本当にいるか」「正解が唯一か」は、
解かせてみないと分からない。ここはその手順。

## 原則

**素の状態で解かせること。** 生成した文脈をそのまま持ったまま解いても、自分の作った答えを
なぞるだけで何も検出できない。サブエージェントを使える環境ならそちらへ渡す。使えないなら、
問題文と選択肢だけを切り出したファイルを作り、正解・解説・ラベルを見ずに解く。

**採点は自動でやらない。** どの誤答を選んだかが情報の本体なので、選択の内訳を必ず残す。

## 対象の選び方

全問やると高い。1単元あたり10〜15問を目安に、この優先順で選ぶ。

1. L1 の出力にある「L2で優先して見る」の問題（機械が疑ったもの）
2. 新しく作った単元・新しい形式の問題（前例が無いので事故りやすい）
3. 残りからランダム抽出（偏りを見るために必要。疑わしいものだけ見ると全体像が歪む）

## 3通りの解かせ方

### 1. 選択肢を隠して解かせる

問題文だけを見せて、空所に入る形を自由に答えさせる。

- **正解と同じものを答えた** → 正常（選択肢なしで解ける問題は文法問題として妥当）
- **選択肢に無い別解を答えた** → **正解が唯一でない可能性。** 最重要の検出。
  その別解が本当に成立するなら、問題文に条件を足すか、その別解を誤答として入れる
- **答えられない** → 問題文の情報が足りない。空所の位置か文脈を見直す

単語 cloze ではこれが「空所以外の語彙が難しすぎないか」の検査も兼ねる。
知らない語で詰まったのか、対象語を知らなくて詰まったのかを言わせること。

### 2. 問題文を隠して選択肢だけ見せる

選択肢4つだけを見せて「どれが正解っぽいか」を当てさせる。理由も書かせる。

- **当たった** → リーク。理由を読めばどこが漏れているか分かる（長さ・丁寧さ・形の不自然さ・
  他3つが明らかに崩れた形になっている、など）
- **外した／根拠が無い** → 正常

L1 の統計検査（長さ・語数）はバッチ単位でしか出ないので、**個別の問題のリークはここでしか見えない。**

### 3. 勘違いを持つ生徒として解かせる — 本命

誤答ごとに、`distractor_notes` に書いた勘違いを持つ生徒として解かせる。

> あなたは「仮定法だと気づかず時制を動かしていない」という勘違いを持つ高校生です。
> この問題をその理解のまま解いてください。

- **狙った誤答を選んだ** → その誤答は機能している
- **正解を選んだ／別の誤答を選んだ** → **その誤答は死んでいる。** ラベルどおりの勘違いを
  持つ生徒ですら取らないなら、誰も取らない。作り直し

`distractor_notes` を書かせる縛りは「書けたか」しか見ていない。**書いたとおりに機能するかを
見られるのはここだけ**なので、誤答ラベルを付けた単元では必ず回す。

3つの誤答それぞれについて回すと3倍かかるので、まずは L1 が疑った問題と、
ラベルの文言が抽象的な誤答（「文法を理解していない」のような、勘違いを特定していないもの）から。

## 報告への戻し方

落ちた問題は、**何が起きたかと直し方をセットで**書く。判定だけでは直せない。

```
- No.27 選択肢を隠しても解けた。問題文の "since" が答えを決めている
  → 時制のヒントを問題文から外し、選択肢側で問う形に
- No.8 誤答3「仮定法だと気づかず時制を動かしていない」を、その勘違いを持つ生徒役が
  選ばなかった（正解を選んだ）
  → 「had known → knew」の形に変え、直説法の過去と見分けさせる
- No.15 選択肢を隠したら、正解以外に "to have been" も成立すると答えた
  → 問題文に時の副詞句を足して1つに絞る
```

## 投入後のループ（L3）

セルフ受験は投入前の代用でしかない。本物のデータは `grammar_answers.chosen` に溜まる。

- **N回出題されて1度も選ばれていない誤答** を洗い出す → 死んだ誤答の実測
- 管理画面の `/api/grammar/admin/distractors` に集計軸を足せば見える
- 出てきたパターンは `rules.md` に足し、次の生成の縛りにする

いまは手動。定期的に回すなら別の仕組みに寄せること（このスキルの担当ではない）。
